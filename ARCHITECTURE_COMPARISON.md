# Сравнение архитектур для классификации храпа

## Обзор

В проекте реализованы две архитектуры для детекции храпа:
1. **Random Forest** (существующая)
2. **Decision Tree** (новая, согласно ТЗ)

## Анализ существующей архитектуры (Random Forest)

### Проблемы
- ❌ **Несоответствие признаков**: ожидается 25, но получается 28
- ❌ **Сложность**: Random Forest с 100 деревьями
- ❌ **Ресурсы**: большой размер модели, медленный инференс
- ❌ **Интерпретируемость**: сложно понять логику принятия решений

### Ошибки в логах
```
❌ Ошибка при работе с реальными данными: X has 28 features, but StandardScaler is expecting 25 features as input.
```

## Новая архитектура (Decision Tree)

### Преимущества
- ✅ **Точное соответствие ТЗ**: ровно 30 признаков
- ✅ **Простота**: одно дерево решений
- ✅ **Ограничения сложности**: max_depth ≤ 5, min_samples_leaf ≥ 10
- ✅ **Интерпретируемость**: каждое решение понятно
- ✅ **Ресурсы**: малый размер (~1-5 КБ), быстрый инференс (<50 мс)

### Архитектура признаков
```
30 признаков = 20 (аудио) + 7 (акселерометр) + 3 (смешанные)
```

#### Аудио признаки (20)
- **4 полосы частот** × **5 признаков** = 20 признаков
- Полосы: Breath (100-400 Гц), Snore (400-1000 Гц), Speech (1000-4000 Гц), High (4000-7000 Гц)
- Признаки: mean, max, std, доля выше порога, тренд

#### Акселерометр (7)
- Средняя амплитуда |Δ| по X/Y/Z (3)
- Максимальная амплитуда |Δ| по X/Y/Z (3)
- Доля подвижных тиков (1)

#### Смешанные (3)
- Snore/Breath отношение
- Snore/Speech отношение
- Breath_autocorr_lag1 (регулярность дыхания)

## Рекомендации

### 1. Переход на Decision Tree
**Причины:**
- Полное соответствие техническому заданию
- Оптимальные характеристики для ESP32
- Лучшая интерпретируемость результатов
- Простота отладки и настройки

### 2. Этапы перехода
1. **Валидация на реальных данных** (текущий этап)
2. **Оптимизация гиперпараметров** (глубина, критерий)
3. **Селекция признаков** (выбор наиболее информативных из 30)
4. **Квантование** (приведение к int8)
5. **Развертывание на ESP32**

### 3. Сохранение совместимости
- Оставить Random Forest как fallback
- Создать единый интерфейс для обеих моделей
- Постепенно мигрировать на Decision Tree

## Технические детали

### Постобработка Decision Tree
1. **Медианный фильтр**: 3 окна (0.3 с)
2. **Гистерезис**: подтверждение ≥3 окон, завершение ≥3 окон

### Нормализация
- **Метод**: RobustScaler (median+IQR)
- **Преимущества**: устойчивость к выбросам
- **Применение**: ко всем 30 признакам

### Ограничения сложности
- **max_depth ≤ 5**: предотвращает переобучение
- **min_samples_leaf ≥ 10**: обеспечивает статистическую значимость
- **criterion**: gini/entropy (по валидации)

## Заключение

**Decision Tree архитектура является оптимальным решением** для детекции храпа на ESP32:

✅ **Оптимальна для ESP32**: малый размер, быстрый инференс  
✅ **Интерпретируема**: понятная логика принятия решений  
✅ **Устойчива**: постобработка фильтрует шум
